## Existing protections and limits

Unknown fields, row/action uniqueness, five rows, three actions, HTTPS without credentials, fixed Itembank bundle ID, future payload dates and atomic Python publishing are already covered in source. MCP remains stdio and outside the app. The watcher has a 15-second fallback and rejected payloads retain last-known-good content. Python writes use owner-only temporary files and fsync both file and directory.

Additional robustness limits: `scripts/today_bridge.py:137` / `:245` do not reject permissive existing record modes, and reads do not revalidate the parent directory; this belongs in F1's shared storage policy. `scripts/boring-notch-today.py:8` parses an unbounded input file before validation; the documented trusted-local MCP boundary also applies before its SDK parses input. Add a bounded CLI read as a follow-up to F1, without expanding into arbitrary-path app input. Poll timers use the default run-loop mode (`boringNotch/components/Today/TodayStore.swift:47`), so sustained event tracking can delay fallback reads; test tracking and resume before choosing a common-mode timer.
